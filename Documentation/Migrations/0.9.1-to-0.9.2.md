# 0.9.1 → 0.9.2

## Method names gained a device suffix

**Summary.** No suffix is CPU. `IP` is in-place CPU. `X` is GPU. `XIP` is in-place GPU. `OP` / `IPOP` and the operators stay unsuffixed.

**Why.** `_IP`, and GPU methods with no suffix, made the device ambiguous.

**Migrate.**

- Replace `_IP` with `IP`. These names do not follow that substitution:

| Old | New |
|-----|-----|
| `Abs_IP` | `AbsIP` |
| `AbsX_IP` | `AbsXIP` |
| `ReverseX_IP` | `ReverseXIP` |
| `Transpose_IP` | `TransposeXIP` |
| `Append_IP` | `AppendIP` |
| `Nan_to_num` | `NanToNumX` |
| `Nan_to_num_IP` | `NanToNumXIP` |
| `Aces_approx` | `AcesApprox` |
| `Aces_approx_IP` | `AcesApproxIP` |
| `Vector3.OP_IP` | `Vector3.IPOP` |
| `Log_IP` | `LogXIP` |

- GPU methods that had no `X` now have one:

| Old | New |
|-----|-----|
| `Reciprocal` / `Reciprocal_IP` | `ReciprocalX` / `ReciprocalXIP` |
| `Diff` / `Diff_IP` | `DiffX` / `DiffXIP` |
| `Normalise` / `Normalise_IP` | `NormaliseX` / `NormaliseXIP` |
| `Transpose` / `Transpose_IP` | `TransposeX` / `TransposeXIP` |
| `Cross` | `CrossX` |
| `MatrixAdd` … `MatrixMultiply` | `MatrixAddX` … `MatrixMultiplyX` |
| `ReduceOP` | `ReduceOPX` |
| `Mask` / `Filter` / `Partition` | `MaskX` / `FilterX` / `PartitionX` |
| `CompareEquals` / `CompareNotEquals` / `Compare` | `CompareEqualsX` / `CompareNotEqualsX` / `CompareX` |
| `GetColumnAsVector` | `GetColumnAsVectorX` |
| Column `GetSliceAsVector` / `GetSliceAsArray` | `GetSliceAsVectorX` / `GetSliceAsArrayX` |
| `Vector3.Magnitude` / `Distance` / `Dot` / `Cross` / `Normalise` | the same names with `X` |
| `VOP` | `VOPX` |
| `Vector3.OP` | `Vector3.OPX` |

- `Concat` is rows only. Column concat is `ConcatColumnX`.

## Old read methods are gone

**Summary.** `RetrieveReadOnlySpan()` is the read. `GetRowAsArray(row, noSync)` and `GetCpuReadOnlySpan()` are gone.

**Why.** The old reads did not agree on whether they synced, so a GPU result could be read stale.

**Migrate.**

- Replace those calls with `RetrieveReadOnlySpan()`.
- Do not open `CpuScope` just to read.

## Pin with `GpuScope`

**Summary.** You can no longer pin a buffer by hand. Use `GpuScope.Begin`.

**Why.** An unpinned buffer can be evicted while a kernel is still using it.

**Migrate.**

- Wrap the launch in one `using (GpuScope.Begin(output, inputs))`.
- Do not open a second scope for the same launch.
